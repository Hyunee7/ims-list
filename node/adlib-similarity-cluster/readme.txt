사용 방법 (도스 파라미터 입력 예시)

1. 파라미터 없이 실행할 때 (원래대로 처리)
지정한 기본 경로인 ./midi_files 폴더 내의 파일들을 검색합니다.
bash
node index.js
코드를 사용할 때는 주의가 필요합니다.
2. 특정 디렉토리 경로를 매개변수로 줄 때
원하는 폴더 경로(절대 경로 및 상대 경로 모두 가능)를 뒤에 한 칸 띄우고 입력합니다.
bash
node index.js C:\Games\Doom\Music
코드를 사용할 때는 주의가 필요합니다.
또는 상대 경로도 지원합니다:
bash
node index.js ../adlib_collection
코드를 사용할 때는 주의가 필요합니다.






AdLib 파일(또는 변환된 MIDI/오디오 파일)들이 담긴 디렉토리를 탐색하여, 곡 간의 멜로디 유사도를 계산하고 유사한 곡끼리 그룹(클러스터링)으로 묶어주는 Node.js 프로그램을 구현해 보겠습니다.
여기서는 파일 변환 및 분석이 가장 용이한 MIDI(.mid) 파일 기반의 분석을 기준으로 작성되었습니다. 만약 원본 AdLib 파일(.ims, .rol) 형태라면 미리 MIDI로 일괄 변환해 두시거나, Node.js용 OPL 렌더러 모듈을 붙여야 합니다. 여기서는 가장 대중적이고 정확도가 높은 '음표 시퀀스 편집 거리(Levenshtein Distance)' 알고리즘을 사용합니다.

🛠️ 프로젝트 설정

먼저 프로젝트 디렉토리를 만들고 필요한 라이브러리를 설치합니다. MIDI 파일에서 음표(Note) 데이터만 쏙 뽑아내기 위해 @tonaljs/midi 또는 @joshua-schimpf/midi-parser 같은 라이브러리를 사용할 수 있으나, 가볍고 순수 Node.js로 동작하는 @tonejs/midi를 추천합니다.

mkdir adlib-similarity-cluster
cd adlib-similarity-cluster
npm init -y
npm install @tonejs/midi fast-levenshtein

• @tonejs/midi: MIDI 파일을 파싱하여 음정(Pitch)과 시간 데이터를 추출합니다.
• fast-levenshtein: 두 음표 시퀀스 문자열 간의 편집 거리를 빠르게 계산합니다.




.ims, .rol, .sop, .mid 네 가지 확장자를 모두 지원하고, 명령프롬프트(도스 매개변수)로 대상 디렉토리 경로를 입력받을 수 있는 Node.js 코드를 작성했습니다.
AdLib 포맷인 .ims, .rol, .sop 파일은 바이너리 구조가 달라 직접 파싱하려면 복잡한 파서가 필요하므로, 이 코드에서는 각 파일 형식의 데이터 바이트 배열(바이너리 패턴) 자체를 시퀀스로 변환하여 유사도를 비교하거나, .mid 파일인 경우 기존처럼 음표 데이터를 활용하도록 이중 구조로 설계했습니다.

🛠️ 필요한 라이브러리 설치

먼저 터미널에서 아래 라이브러리들을 설치해 주세요. (@tonejs/midi와 fast-levenshtein이 사용됩니다.)
bash
npm install @tonejs/midi fast-levenshtein
코드를 사용할 때는 주의가 필요합니다.




파일이 많아도 답답하지 않게 현재 진행 상황(처리 중인 파일, 퍼센트)을 실시간으로 보여주고, 결과 출력 시 그룹의 기준(중심)이 되는 곡과 각 곡이 기준 곡과 얼마나 유사한지(%)를 명확하게 보여주도록 코드를 업그레이드했습니다.


🖥️ 실행 시 콘솔 출력 예시

text
🔍 대상 디렉토리: D:\DOS_Games\Music

📂 총 5개의 파일을 찾았습니다.
--------------------------------------------------
[1/2] 파일 특징 추출 중... (100.0%) - KART_THEME.mid             
✅ 파일 특징 추출 완료! (성공: 5곡)

[2/2] 곡 간 유사도 비교 시작...
✅ 유사도 분석 완료!

==================================================
🎵 유사 곡 그룹화 결과 (Threshold: 65%)
==================================================

▶️ [그룹 1] ------------------------------------
  👑 기준 곡: STAGE1_MAIN.ims
  👥 유사한 곡 리스트 (총 3곡):
    - [92.4% 일치] STAGE1_ARRANGE.ims
    - [71.5% 일치] STAGE1_BOSS.rol

▶️ [그룹 2] ------------------------------------
  👑 기준 곡: INTRO_THEME.sop
  👥 유사한 곡 리스트 (총 1곡):
    (이 곡과 유사한 다른 곡을 찾지 못했습니다.)

▶️ [그룹 3] ------------------------------------
  👑 기준 곡: KART_THEME.mid
  👥 유사한 곡 리스트 (총 1곡):
    (이 곡과 유사한 다른 곡을 찾지 못했습니다.)

==================================================
코드를 사용할 때는 주의가 필요합니다.




곡이 많아질수록 2단계인 유사도 비교 연산 횟수가 기하급수적으로 증가하므로, 이 구간의 진행상황도 실시간 퍼센트와 게이지바 형태로 콘솔에 업데이트되도록 수정했습니다.


🖥️ 유사도 비교 시 출력 화면 (실시간 실효 화면 예시)

이제 두 번째 단계가 실행될 때 화면이 멈춰있지 않고, 아래와 같이 현재 어떤 파일(기준 곡)을 잡고 비교 행렬을 채워나가는지 실시간으로 한 줄 업데이트됩니다.
text
[2/2] 곡 간 유사도 비교 시작...
      연산 진행률... (45.2%) [23/50] - 기준 곡: STAGE2_BGM.rol 
코드를 사용할 때는 주의가 필요합니다.
연산이 모두 끝나면 개행(\n) 처리가 되면서 기존에 작성했던 스코어판 형태의 깔끔한 결과 데이터가 쏟아져 나옵니다. 곡 수 백 개 단위의 헤비한 폴더를 집어넣어도 진행 추이를 직관적으로 파악하실 수 있습니다.




지정한 디렉토리뿐만 아니라 그 안에 있는 모든 하위 디렉토리(Subdirectories)까지 샅샅이 탐색하여 .ims, .rol, .sop, .mid 파일을 찾아내고 분류하도록 코드를 수정했습니다.
이를 위해 하위 디렉토리를 재귀적으로 탐색하는 기능을 추가했으며, 콘솔 창에서 파일이 어느 폴더에 위치해 있는지 쉽게 구별할 수 있도록 파일명 앞에 상대 경로를 포함하여 출력하도록 고도화했습니다.
